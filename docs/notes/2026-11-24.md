## 2. LLM 호출기가 하는 일 / 안 하는 일

**한다**: `Prompt`를 받아 → 모델 API를 부르고 → 받은 응답을 **손대지 않고** 넘긴다. 그리고 걸린 시간·비용을 잰다.

**안 한다**: 응답에서 글자 뽑기, 검사, 화면 출력 → 나중에 만들 **출력처리기**의 일.

> 왜 나누나? 지금 `main.ask()`는 "모델 부르기 + 글자 뽑기 + 화면 출력 + 통계 정리"를 한 함수에서 다 한다.
> 이러면 모델을 바꿀 때 화면 출력 코드까지 건드려야 한다. 나누면 얻는 것 세 가지:
>
> 1. **모델 교체**가 쉽다 (호출기만 갈아 끼움)
> 2. **호출 방식 차이**(Agent SDK vs Messages API)를 호출기 안에 가둔다
> 3. **지연·비용을 재는 곳**이 한 군데로 정해진다

---

## 3. C0에서 정한 네 가지 (모두 추천안 선택)

| 질문 | 결정 | 이유 |
| ---- | ---- | ---- |
| 응답을 어떤 모양으로 넘기나 | 공급자 객체 **원본 그대로** 봉투(`RawResponse`)에 담기 | 공통 모양으로 바꾸는 순간 그게 "파싱"이다 |
| 스트리밍은? | 이벤트를 **하나씩 흘려보내고**, 끝나면 전체도 꺼낼 수 있게 | 지금처럼 답이 실시간으로 화면에 나와야 한다 |
| 세션은 누가 여닫나 | **호출기**가 (`async with caller:`) | `main`이 SDK를 몰라야 모델 교체가 쉽다 |
| 재시도는? | **일시 오류만, 아직 아무것도 안 내보냈을 때만** | 이미 화면에 나간 답을 또 출력하거나 비용을 두 번 내지 않게 |

## 4. 만든 것 (그림으로)

```python
async with caller:                  # 세션 열기 (호출기가 소유)
    call = caller.stream(prompt)    # 호출 시작
    async for event in call:        # 원시 이벤트가 하나씩 도착 → 출력처리기가 소비
        ...
    raw = call.response             # 다 받은 뒤: 전체 이벤트 + 측정값
```

| 파일 | 역할 |
| ---- | ---- |
| `chatbot/llm_caller.py` | 공통 모양. `BaseCaller`(호출기 부모), `CallStream`(흘려보내며 모으기), `RawResponse`·`CallMetrics`(결과 값) |
| `chatbot/callers/fake.py` | `FakeCaller`: 정해 둔 이벤트를 그대로 내보내는 가짜. 네트워크·비용 0 |
| `tests/test_llm_caller_contract.py` | 모든 호출기가 통과해야 하는 계약 테스트 9개 |

### 값 vs 객체 (오늘 가장 많이 헷갈린 부분)

| 종류 | 클래스 | 만드는 법 |
| ---- | ------ | --------- |
| **값**: 한 번 만들면 안 바뀜 | `RawResponse`, `CallMetrics` | `@dataclass(frozen=True)` |
| **객체**: 상태가 계속 바뀜 | `BaseCaller`, `CallStream`, `FakeCaller` | 일반 클래스 + `__init__` |

> 판단 기준: "다음 단계로 **넘겨주는 데이터**"면 값, "**일을 하면서** 상태가 바뀌는 것"이면 객체.

## 5. 계약 테스트 9개 (호출기라면 지켜야 할 약속)

| # | 약속 | 왜 필요한가 |
| - | ---- | ----------- |
| 1 | 이벤트를 **같은 순서, 같은 객체(`is`)**로 내보낸다 | "원시 응답을 손대지 않는다"의 증거 |
| 2 | 공급자가 받은 것 = 받아야 할 것 | 호출기가 프롬프트를 바꿔 보내면 안 된다 |
| 3 | `async with` 밖에서 부르면 오류 | 세션 없이 부르는 건 프로그래밍 실수 |
| 4 | 다 받기 전에 `.response`를 읽으면 오류 | 일부만 받은 답을 "짧은 답"으로 오해하지 않게 |
| 5 | 스트림은 **한 번만** 돌 수 있다 | 두 번째 소비자가 "빈 답"을 받지 않게 |
| 6 | 앞 호출을 다 받기 전에 다음 호출하면 오류 | 두 답의 이벤트가 섞이지 않게 |
| 7 | 중간에 끊고 나가도 다시 열면 호출 가능 | Ctrl+C 뒤에 챗봇이 영원히 막히지 않게 |
| 8 | 응답에 공급자·요청 모델·시도 횟수가 담긴다 | 모델 교체 시 트레이스로 비교하려고 |
| 9 | 모델을 안 정하면 `None` (공급자 기본값) | 명세 |

**`impl` fixture**: 테스트가 "어떤 호출기인가"를 모르게 만들었다. 지금은 `[fake]` 하나뿐이지만, C2에서 Agent SDK 호출기를 `IMPLS`에 **한 줄 추가**하면 9개 약속을 그대로 검사받는다. 이게 이점 1(모델 교체)의 안전장치다.

## 6. 오늘 겪은 실수와 배운 것

| 겪은 일 | 원인 | 배운 것 |
| ------- | ---- | ------- |
| `FakeCaller(responses=...)`가 "그런 인자 없음" | `from attr import dataclass` — 표준 `dataclasses`가 아니라 서드파티 attrs. attrs는 직접 쓴 `__init__`을 **덮어쓴다** | 편집기 자동 import를 의심하자. 표준은 `from dataclasses import dataclass` |
| `FrozenInstanceError` | 상태가 바뀌는 클래스에 `frozen=True` | 값과 객체를 구분 (4절 표) |
| 새 테스트 3개가 `NameError: pytest` | `import pytest` 누락 | Red도 **기대한 이유로** 실패해야 의미가 있다 |
| 예외는 났는데 테스트 실패 | 오류 메시지에 `match` 문구(`not consumed`, `in progress`)가 없음 | `match`는 메시지 내용까지 검사한다. 테스트가 명세이므로 구현을 맞춘다 |
| 이미 통과하던 테스트까지 전부 실패 | `stream()`의 코드 두 줄이 `__init__` 안에 붙여 넣어짐 | 한꺼번에 깨지면 새 기능이 아니라 **공통 경로**(생성자)가 망가진 것 |
| `ruff`가 `aiter`/`anext`를 모름 | `pyproject.toml`에 파이썬 버전이 없었음 | `target-version = "py312"` 추가 |
| "세션 다시 열기" 버그를 테스트가 못 잡음 | 구현은 있었지만 그 상황을 검사하는 테스트가 없었음 | **일부러 망가뜨려 보기**(mutation)로 구멍을 찾고 테스트로 메웠다 |

### 일부러 망가뜨려 확인한 것 (모두 테스트가 잡음)

- 이벤트를 복사해서 내보내기 → `is` 비교가 잡음 (`==`였다면 통과했을 것)
- 순서 뒤집기, 이벤트 안 모으기
- 세션 검사 / 겹친 호출 검사 / 소비 전 `.response` 검사 / 한 번만 순회 검사 제거
- 세션을 닫을 때 진행 중 스트림을 안 비우기 (처음엔 못 잡음 → 테스트 7 추가 후 잡음)

## 7. 일부러 남겨 둔 것 (다음 단계에서 테스트 먼저)

- `attempts=1`은 지금 상수. 재시도를 만드는 **C4**에서 실제 횟수가 된다.
- 공급자가 스트림 도중 예외를 내면 `done`이 영원히 `False` → 다음 호출이 막힌다. 오류 분류를 다루는 **C4**에서 고친다.
- 지연·첫 출력 시간·사용량·비용은 아직 없다 → **C3**.
