# 2부: 프롬프트 파이프라인

프롬프트 구성기의 역할: 시스템 지시, 예시, 외부 문서, 대화 기록, 사용자 입력을 조합해 **LLM에 전달할 최종 입력**을 만든다.
프롬프트는 긴 문자열 하나가 아니라 역할이 나뉜 메시지 목록 + (도구 정의, 응답 형식) + 메타데이터다.
코드는 `chatbot/prompt_builder.py`, 프롬프트 파일은 `prompts/*.yaml`.

## P0. 설계: 왜 독립 단위로 두나

프롬프트 문구가 비즈니스 로직 안에 문자열로 박혀 있으면, 프롬프트를 고칠 때마다 코드가 바뀌고 테스트할 지점이 없다.
세 층으로 나눴다.

| 층 | 위치 | 성격 |
| -- | ---- | ---- |
| 템플릿 | `prompts/*.yaml` | 데이터. 사람이 고치는 문구, 예시 |
| 구성기 | `chatbot/prompt_builder.py` | **순수 함수**. 같은 입력이면 항상 같은 출력 → 스냅샷 테스트, 프롬프트 캐싱 가능 |
| 어댑터 | `main.ask()` | 특정 SDK 호출 형태로 바꾸는 곳. SDK 사정은 여기에만 |

구성기의 결과 `Prompt`는 특정 SDK에 묶이지 않은 중립 형태다(`system`, `messages`, `dropped_turns`, `document_count`).

**프롬프트 드리프트 3종**과 잡는 방법

| 드리프트 | 예 | 잡는 장치 |
| -------- | -- | --------- |
| 의도하지 않은 렌더링 변화 | 리팩터링 중 빈 줄 하나가 사라짐 | 골든 스냅샷 테스트 (P7) |
| 의도한 수정의 부작용 | 지시를 고쳤더니 다른 질문의 답이 나빠짐 | EDD v1 vs v2 비교 (레벨 2, 예정) |
| 모델 변경 | 같은 프롬프트, 다른 모델 버전 | 트레이스의 `prompt_version` + `model`로 구간 나누기 |

**신뢰 수준에 따른 배치**

| 자리 | 내용 | 신뢰 |
| ---- | ---- | ---- |
| `system` | 우리가 쓴 지시와 예시 | 신뢰 |
| `messages` | 사용자 입력, 외부 문서 | 신뢰하지 않음. **절대 `system`에 넣지 않는다** |

## P1–P2. 기본 구조, 템플릿, YAML (`f9a635e`)

| 항목 | 결정 |
| ---- | ---- |
| 데이터 모델 | `Message(role, content)`, `Prompt` 모두 `frozen` dataclass (조립 뒤 바뀌지 않음) |
| 템플릿 엔진 | 표준 `string.Template` (새 의존성 없음). `get_identifiers()`(3.11+)로 쓰인 변수 목록을 얻는다 |
| 변수 규칙 | 빠진 변수·쓰이지 않는 변수 모두 오류(`TemplateError`). 치환은 **한 번만** (값 안의 `$name`은 다시 치환되지 않음). `$$`는 `$` |
| 파일 형식 | Markdown 대신 **YAML** (사용자 제안). `id`·`description`·`variables`·`system`·`examples`를 구조로 담고 검증할 수 있다 |
| YAML 읽기 | `yaml.safe_load`만 (`!!python/...` 태그로 코드 실행 차단). 필수 키 누락, 모르는 키(오타), 타입 오류를 모두 `{path}:` 접두어와 함께 오류로 |
| 선언 검사 | `variables`에 선언한 이름 = 템플릿이 실제로 쓰는 이름 |
| 해시 안정성 | `.gitattributes`로 `prompts/*.yaml`을 LF로 고정. Windows 체크아웃이 CRLF로 바꾸면 해시가 달라진다 |
| 앱 연결 | `main.py`의 `SYSTEM_PROMPT` 상수를 `prompts/chat.yaml`로 옮김. 프롬프트 파일이 깨졌으면 SDK 연결 전에 실패(fail fast)하고 로그에 남김 |

YAML의 함정 (테스트로 고정)
- **Norway problem**: `no`, `yes`, `on`이 문자열이 아니라 `False`/`True`가 된다 → 타입 검사로 잡음.
- `|` 블록은 끝에 줄바꿈을 붙인다 → `system`을 `rstrip`.
- CRLF 파일, 키가 숫자인 경우, 깨진 YAML도 각각 테스트.

배운 것
- **프롬프트를 파일로 옮긴 뒤 해시가 `a3981547b638`로 그대로인 것을 실제 실행으로 확인** = 이 리팩터링이 모델 입력을 한 글자도 바꾸지 않았다는 증거.
- `pytest.raises(match=...)`의 정규식이 느슨하면 **다른 이유로** 통과한다. 예시 테스트의 `match="examples"`는 "unknown keys: examples" 오류로도 통과했다 → `match=r"examples\[0\]"`로 좁힘.
- 어떤 테스트도 `main.py`를 import하지 않으면 문법 오류가 있어도 테스트가 모두 통과한다(붙여 넣다 잘린 줄로 실제 `SyntaxError`가 났었음) → `import main` 스모크 테스트.
- 시스템 지시는 **한 번만 렌더링하고 그 값을 SDK 설정과 트레이스가 함께 쓴다**(단일 출처). 두 곳에서 따로 렌더링하면 변수가 생기는 순간 기록이 실제와 어긋난다.

## P3–P4. 대화 기록, 예산, 문서 (`98bffeb`)

대화 기록 규칙
- `user`로 시작해 `user`/`assistant`가 번갈아 나오고 `assistant`로 끝나야 한다(이번 입력이 그 뒤에 붙으므로). 어기면 `PromptBuildError`(위치와 기대 역할을 메시지에).
- 예산 `max_chars`는 **시스템 지시를 포함한 전체** 크기. 넘으면 가장 오래된 턴부터 **user+assistant 쌍 단위로** 버린다(반쪽 턴이 남으면 구조가 깨진다).
- **이번 입력은 절대 버리지 않는다.** 시스템 + 문서 + 이번 입력만으로 넘으면 조용히 자르지 않고 오류.
- 버린 턴 수는 `dropped_turns`로 보고한다(관측 가능해야 드리프트를 분석할 수 있다).

문서 규칙
- 이번 user 메시지에서 **질문 앞에** `<documents><document index="1" source="...">…</document></documents>`로 넣는다.
- 문서는 신뢰하지 않는 외부 텍스트 → 내용은 `xml.sax.saxutils.escape`로 `& < >` 이스케이프. 문서 안의 `</documents>`가 블록을 탈출하지 못한다.
- 출처는 큰따옴표 속성 안에 들어가므로 `"`도 이스케이프해야 한다. `escape()`는 기본으로 `"`를 바꾸지 않아 `{'"': "&quot;"}`를 추가로 넘긴다(`quoteattr`는 내용에 따라 따옴표 종류를 바꿔서 쓰지 않음).
- 예산은 **이스케이프한 뒤의 크기**로 센다(모델이 실제로 받는 크기).

배운 것
- 경계값은 쌍으로 고정한다(예산 43 → 유지, 42 → 버림). 그래야 `>`와 `>=`의 차이가 테스트에 걸린다.
- mutation으로 테스트를 검증: 쌍 단위 버림, 고정 크기 검사, 홀수 길이 검사, 예산에 문서 포함, 이스케이프(내용·속성·`"`)를 하나씩 망가뜨려 모두 잡히는지 확인했다.
- Red가 `NameError`(`Document` import 누락)나 `TypeError`(매개변수 없음)면 아직 Red가 아니다. 껍데기부터 만든다.
- 오류 메시지를 의역하다가 뜻이 뒤집힌 일이 있었다("must end with user"). 메시지도 명세의 일부다.
- 예산 계산에 `user_input`을 쓰고 문서를 빠뜨린 버그 → "예산에 문서가 포함된다" 테스트가 잡음.

## P5. 예시 few-shot (`7d0a3a6`)

- YAML의 선택 키 `examples: [{user, assistant}, ...]` → 시스템 지시 뒤에 `<examples><example><user>…</user><assistant>…</assistant></example></examples>`.
- 예시는 우리가 쓴 것(신뢰)이라 이스케이프하지 않는다. 대신 **불러올 때** 닫는 태그(`</examples>`, `</example>`, `</user>`, `</assistant>`)가 들어 있으면 오류.
- 예시는 템플릿 치환 대상이 아니다(예시 안의 `$`가 변수로 해석되지 않게).
- 예시가 없으면 빈 줄도 붙이지 않는다 → 기존 프롬프트의 해시가 그대로.
- 예시 항목에 `user`, `assistant` 외의 키가 있으면 오류.

배운 것
- 선택 키를 `data["examples"]`로 읽어 `KeyError`, 파싱 함수를 만들고 호출하지 않은 실수 → 각각 테스트가 잡음.
- **살아남은 mutation = 빠진 테스트.** "예시에 여분의 키 허용"으로 바꿔도 아무 테스트도 실패하지 않아 `test_example_with_extra_key_is_an_error`를 추가했다.
- SonarQube 인지 복잡도 경고 → 검사 로직을 `_check_example_text`로 추출.

## P6. 버전과 메타데이터 (`0f25fe3`)

기존 `prompt_version`(렌더링된 시스템 지시의 해시)의 문제
- 바뀌지 않았는데 바뀐 걸로 나옴: `${today}` 같은 변수가 생기면 템플릿은 그대로인데 해시가 매일 바뀐다.
- 바뀌었는데 안 바뀐 걸로 나옴: 문서 태그 형식 같은 조립 코드가 바뀌어도 시스템 지시 해시는 그대로다.

**각 변화를 맞는 열쇠로 추적**

| 무엇이 바뀌었나 | 추적하는 값 |
| --------------- | ----------- |
| 프롬프트 파일의 의미 내용(지시 템플릿, 예시) | `prompt_version` = `spec_version(spec)`: `system` + `examples`를 정규화한 JSON(`sort_keys`, 고정 구분자)의 SHA-256 앞 12자리 |
| 조립 규칙 코드 | `git_commit` + 골든 스냅샷(P7) |
| 변수 값(날짜 등) | 버전이 아니다. 값으로 기록할 대상 |
| 실제로 보낸 시스템 텍스트 | `system_hash` (예전 `prompt_version`과 같은 계산 → 예전 트레이스와 잇는 고리) |

- `id`, `description`, YAML 주석·따옴표·들여쓰기는 모델이 보지 않으므로 해시에서 뺀다. 파일 바이트가 아니라 **파싱한 내용**을 해시한다.
- `Prompt.metadata()`: `message_count`, `dropped_turns`, `document_count`, `total_chars`. **내용은 담지 않는다** → 운영 로그에도 남길 수 있다(테스트로 강제). `total_chars`는 예산과 같은 단위(`_size`)로 센다.
- `main.py`가 턴마다 `build_prompt`로 조립하고, 트레이스 `turn.prompt`에 메타데이터를 남긴다. `docs/tracing.md`에 계산 방식 변경 시점을 기록했다.

배운 것
- "무언가를 하지 않는다" 테스트(설명은 해시에 영향 없음, 메타데이터에 내용 없음)는 껍데기(`""`, `{}`)에서 저절로 통과한다 → Green 뒤 mutation으로 확인.
- `sort_keys=True` 제거 mutation은 살아남았다. dict를 늘 같은 순서로 만들기 때문이다. 테스트로 고정할 동작이 없는 **방어 장치**라 그대로 둔다.
- **`main.py`는 `build_prompt`를 안 쓰고 있었다**(사용자 지적). Agent SDK는 세션이 대화 기록을 들고 있어서 `messages` 전체를 넘길 자리가 없다. 어댑터(`ask`)가 마지막 user 메시지만 보내도록 연결했다. 대화 기록·예산 기능은 Messages API처럼 매번 전체를 보내는 경로를 위해 남겨 둔다.
- 연결하면서 **테스트 197개가 모두 통과하는 상태로** 두 버그가 있었다: `ask` 호출 인자 불일치(모든 질문이 실패), `prompt_version`/`system_hash` 값 뒤바뀜. 실제로 실행해 보고서야 드러났다 → `main` 흐름 테스트를 P7보다 먼저 하기로.

## P8. `main` 흐름 테스트 (`6762105`)

- `main()`이 외부와 닿는 두 곳을 키워드 인자로 받는다: `client_factory=ClaudeSDKClient`, `read_input=read_user_input`. 기본값이 실제 것이라 `__main__`은 그대로다. (`monkeypatch`로 이름을 바꿔치기하는 방법보다 시그니처에 드러나는 주입을 택함.)
- 테스트 도구: `FakeClient`(받은 query 기록, 스크립트대로 응답·예외), `ListTracer`, `anyio.run(partial(...))`(키워드 인자 전달).
- 고정한 동작: 세션 옵션(`system_prompt`, `tools=[]`, `setting_sources=[]`), 이번 턴만 전송, 거부된 입력은 전송·`prompt` 기록 없음, SDK 오류 뒤에도 대화 계속, `exit`, 버전 필드, 대화 내용이 운영 로그에 없음.

배운 것
- 이미 있는 동작을 고정하는 **특성화 테스트**는 Green으로 시작한다 → mutation으로 검증. 지난 버그(`ask` 인자)를 다시 넣으니 7개가 실패했다.
- 시그니처에만 매개변수를 추가하고 본문에서 쓰지 않았더니 **테스트가 실제 Claude Code CLI를 띄웠다.** 바꿔 끼울 지점은 실제로 연결돼야 의미가 있다.
- `assert a != b`는 두 값이 뒤바뀐 버그를 잡지 못한다 → **각각 정답과 비교**(`== spec_version(SPEC)`).
- `while True`는 입출력 방식(터미널 REPL)의 문제이고, 모델 통신 방식과는 별개다.

| | Messages API (상태 없음, 매번 전체 기록 전송) | Agent SDK (세션이 기록 보관, 이번 턴만 전송) |
| - | - | - |
| 터미널 | `while True` + `messages` 리스트를 직접 쌓음 | **지금 구조** |
| 웹 서비스 | 일반적인 운영 챗봇: 요청마다 저장소에서 기록을 꺼내 `build_prompt(history=...)` | 사용자마다 세션 프로세스가 필요해 드묾 |

## P7. 골든 스냅샷 (`b54e67a`)

- `tests/snapshots/*.txt`: `=== system ===`, `=== user ===`, `=== metadata ===` 구획의 **사람이 읽는 텍스트**. JSON은 줄바꿈이 이스케이프되어 한 줄에 몰리므로 PR diff를 읽을 수 없다.
- 스냅샷이 없으면 실패(CI에서 조용히 생성되지 않게). `UPDATE_SNAPSHOTS=1`일 때만 갱신. LF로 쓰고 `.gitattributes`로 고정.
- 불일치하면 `difflib.unified_diff`로 바뀐 줄만 보여 준다(pytest 기본 비교는 긴 문자열을 잘라서 보여 줌).
- 두 개만: 실제 운영 프롬프트(`chat_basic`), 모든 구성 요소를 담은 시나리오(`full`: 변수, 예시, 기록, 이스케이프할 문서, 버려지는 턴).

배운 것
- **스냅샷은 라벨이다.** 처음 생성한 파일은 현재 구현의 결과일 뿐이라, 사람이 읽고 맞다고 판단해야 정답이 된다. 실패할 때마다 `UPDATE_SNAPSHOTS=1`로 덮어쓰면 도장 찍기가 된다.
- 스냅샷의 예산은 경계 한가운데(255~261 중 258)로 잡는다. 경계에 걸치면 무관한 변화에도 버리는 턴 수가 바뀌어 diff에 두 종류의 변화가 섞인다. 경계는 단위 테스트(43/42)가 맡는다. `dropped_turns == 1`을 먼저 확인해 스냅샷이 엉뚱한 상황을 고정하지 않게 한다.
- 스냅샷을 수십 개로 늘리면 규칙 하나 바꿀 때 전부 실패하고, 결국 일괄 갱신하게 된다 → 대표 시나리오 몇 개만.

## P9. EDD 레벨 1 (`3c1f4bb`)

`evals/run_prompt_eval.py` + `evals/prompt_cases.jsonl`(19개). 모델을 호출하지 않는다(비용 0, 결정적). **실제 운영 프롬프트**(`prompts/chat.yaml`)로 조립한다.

| 종류 | 검사 |
| ---- | ---- |
| 불변식 (모든 케이스, 라벨 불필요) | `system_unchanged`, `structure`, `current_input_last`, `within_budget`, `documents_contained`(문서 블록을 **XML로 파싱**해 수·순서·출처·내용이 원본과 같은지), `minimal_drop`(오래된 것부터, 하나라도 덜 버리면 예산 초과) |
| 라벨 (사람) | `outcome`(성공/오류 종류), `dropped_turns` |

- 케이스: 기본, 예산 경계(같으면 유지, 1 모자라면 버림), 잘못된 기록, 주입 시도(입력의 태그·`${name}`, 문서의 닫는 태그, 출처의 따옴표), 여러 문서, 이미 엔티티처럼 보이는 텍스트.
- 모두 바로 PASS → **eval 자체를 mutation으로 검증**: 내용 이스케이프 제거, 출처 `"` 이스케이프 제거, 예산 `>=`, 최신 턴부터 버림, 입력을 system에 섞음 — 5개 모두 게이트 실패.
- CI에 `Prompt builder eval gate (EDD level 1)` 단계 추가.

배운 것
- 결정적인 구성 요소에서 TDD와 EDD의 차이: 단위 테스트는 규칙 하나씩, eval은 **시나리오 데이터셋**에 불변식을 한꺼번에 적용한다. 데이터셋은 트레이스에서 자랄 수 있고, 레벨 2에서 같은 케이스를 실제 모델에 보내 응답을 채점하는 데 다시 쓴다.
- "문자열에 무엇이 들어 있나"보다 "**모델이 구조를 어떻게 읽을까**"(XML 파싱)를 검사하는 것이 주입 차단을 더 정확히 확인한다.

## 작업 중 겪은 도구·환경 문제

- **cp949**: Windows 콘솔 출력, Git Bash stdin 파이프, 기본 파일 인코딩 모두에서 문제 → 출력·입력·로그 파일 모두 UTF-8을 명시. eval 실행기들도 `sys.stdout.reconfigure(encoding="utf-8")`.
- **이스케이프 표기 변환**: 셸·도구를 거치며 `\u200b` 같은 표기가 실제 보이지 않는 문자로 바뀌어 소스·문서에 들어간 일이 있었다 → 문자열·주석 안의 보이지 않는 문자를 이스케이프로 되돌리는 검사를 돌리고, 규칙으로 남김("소스·테스트·문서의 보이지 않는 문자는 항상 `\uXXXX`"). 2부에서도 같은 일이 있었다: heredoc을 거치며 줄바꿈 이스케이프 표기가 실제 줄바꿈이 되고, 파일 쓰기·편집 도구가 `\u200b` 표기를 실제 문자로 바꿈 → 백슬래시는 `chr(92)`로 조립.
- **`.gitignore`, `.gitattributes`**: 파일 끝 줄바꿈이 없으면 `echo >>`가 같은 줄에 이어 붙는다.
- **줄 길이**: 포매터 기본 88자가 긴 줄을 쪼갬 → `pyproject.toml`에 black·ruff 모두 120.
- **줄바꿈 정책**: 해시·비교 대상(`prompts/*.yaml`, `tests/snapshots/*.txt`)만 `.gitattributes`로 LF 고정. 나머지는 Windows의 `core.autocrlf`에 맡김.

## 역할

프롬프트 구성기가 완성한 입력(`Prompt`)을 받아 **지정된 모델 API를 호출하고, 원시 응답(raw response)을 그대로 다음 단계로 넘긴다.**

| 하는 것 | 하지 않는 것 (다른 단계의 몫) |
| ------- | ----------------------------- |
| `Prompt` → 선택된 API의 호출 형태로 변환 | 응답 파싱(텍스트 블록 추출 등), 변환, 검증 → **출력처리기** |
| 호출, 타임아웃, 재시도, 오류 분류 | 사용자에게 출력(`print`) → 출력처리기 / 앱 |
| 지연·비용 **측정**(관측값 기록) | 입력 거부, `exit` 판정, 트레이스 레코드 조립 → 비즈니스 로직(`main`) |
| 원시 응답을 손대지 않고 반환 | 프롬프트 조립 → 프롬프트 구성기 |

**핵심 원칙: LLM을 호출하는 코드가 비즈니스 로직, 응답 파싱, 사용자에게 반환하는 코드와 한 함수에 섞이지 않는다.**

## 출발점: 지금 `main.ask()`가 섞고 있는 것

| `ask()` 안의 일 | 옮겨 갈 곳 |
| --------------- | ---------- |
| `client.query(...)`, `receive_response()` | LLM 호출기 |
| `AssistantMessage`에서 `TextBlock`만 골라냄 | 출력처리기 (파싱) |
| `print(...)`로 화면 출력 | 출력처리기 / 앱 |
| `ResultMessage`에서 비용·시간을 골라 트레이스용 dict 구성 | 측정은 호출기, 기록 조립은 `main` |
| `logger.debug/info` | 각 단계가 자기 메타데이터만 |

## 얻어야 할 이점 3가지

1. **모델 교체 가능성**
   - 공통 인터페이스(예: `LLMCaller.call(prompt) -> RawResponse`) + 공급자별 구현(어댑터).
   - 공급자·모델은 코드가 아니라 설정으로 고른다. 트레이스에 `provider`, 요청한 모델, 응답한 모델을 남긴다.
   - 모든 구현이 **같은 계약 테스트(contract test)** 를 통과해야 한다.
2. **호출 방식의 차이 관리**: 차이를 구현 안에 가두고, 바깥에는 같은 모양만 보인다.

   | 차이 | Agent SDK (지금) | Messages API |
   | ---- | ---------------- | ------------ |
   | 상태 | 세션이 기록 보관 → 마지막 user 메시지만 | 상태 없음 → `messages` 전체 (대화 기록·예산 기능이 실제로 쓰임) |
   | 인증 | 로컬 Claude Code 로그인 | API 키 (`.env`, 커밋 금지) |
   | 응답 | 메시지 스트림(`AssistantMessage`, `ResultMessage`) | 응답 객체 또는 스트리밍 이벤트 |
   | 수명 | 연결·종료가 있는 세션 | 요청 하나 |
   | 오류 | `ClaudeSDKError` 계열 | HTTP 상태별 예외(429, 5xx, 타임아웃) |

   - 오류는 공통 예외(예: `LLMCallError(kind, retryable)`)로 분류한다. 재시도·타임아웃 정책은 호출기 몫.
3. **지연(latency)과 비용 측정 지점 확보**
   - 호출을 감싸는 **한 곳**에서 시작·첫 응답 조각·끝 시각을 잰다 → `latency_ms`, `time_to_first_token_ms`.
   - 토큰 사용량·비용은 원시 응답에 있는 값을 **측정값으로 기록**한다(응답 해석이 아니라 계측). SDK는 `total_cost_usd`를 주지만 Messages API는 `usage`만 준다 → 단가표로 계산할지 결정.
   - 시계는 주입 가능하게(`TraceWriter`의 `now`처럼) → 지연 측정을 결정적으로 테스트.
   - 트레이스에는 측정값 전체, 운영 로그에는 메타데이터만(원문 금지 규칙 유지).

## 먼저 정할 것

- **원시 응답의 형태**: SDK 객체를 그대로 넘길지, 직렬화 가능한 형태로 감쌀지. 트레이스 기록용 직렬화는 별도로.
- **스트리밍**: 지금은 도착하는 대로 화면에 출력한다. 호출기가 완성된 응답만 넘기면 스트리밍 UX가 사라진다 → 원시 이벤트를 async iterator로 넘기고 출력처리기가 소비하는 구조를 검토. 첫 토큰 지연 측정과도 연결된다.
- **세션 수명**: Agent SDK 세션의 연결·종료를 호출기가 소유할지, `main`이 소유할지.
- **재시도**: 어떤 오류를 재시도할지, 최대 횟수, 재시도로 인한 비용 중복.
